paper(joss): stop describing CI as running the source tree - it runs the published tree

The shipped manuscript said the suite "collects 69 tests; all 69 pass in the source tree under
both PySCF versions in the CI matrix ... and pass again from outside the tree". GitHub Actions
never sees the source tree: it checks out this repository, which does not contain
test_fastpair_ide.py, so its collection is 49, not 69. The 69-vs-49 distinction is stated
correctly in README.md and in paper/software.md and was flattened here anyway, which is the
exact failure this project has already been burned by once - two objects quoted as one.

What the sentence now separates:

  working repository   69 collected, 69 passed, under 2.12.1 and 2.14.0 (local rehearsals,
                       archived under evidence/release_qa/)
  published tree, CI   49 collected: 48 passed, 1 skipped by design, reached twice per arm -
                       in the checked-out tree and from outside it against the installed
                       package

The skipped one is the S22 geometry retrieval, which is not part of an install. The counts are
read off the archived API observation added in the previous commit, not restated from memory.
