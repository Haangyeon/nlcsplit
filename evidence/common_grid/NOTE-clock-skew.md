# 更正：本目录两个 .out 的时间戳是错的（WSL 时钟偏差），数据本身不受影响

日期：2026-10-09（Windows 时钟）。发现方式：给运行产物盖时间时，三处时钟对不上。

## 事实

| 时钟 | 读数（发现问题那一刻） |
|---|---|
| Git Bash（Windows） | 2026-10-09T08:28:55Z |
| PowerShell（Windows） | 2026-10-09T08:28:56Z |
| WSL | 2026-10-09T08:29:21Z |

但两个产物**运行当时** WSL 打出的读数分别是 `2026-10-06T09:06:13Z` 与
`2026-10-06T10:11:29Z`（见文件内 `run_utc=` 行与文件名）。也就是说运行那一刻
WSL 的钟比宿主慢三天左右——它在更晚的一次 WSL 启动里自行同步回来了。

## 影响范围（哪些字段可信、哪些不可信）

- **不可信**：两个 .out 的文件名里的 `YYYYMMDDThhmmZ`、文件内 `run_utc=` 行。
  它们写的是 2026-10-06，实际执行日是 2026-10-09。
- **可信**：每次运行的耗时（`[199 s]` 这类，来自进程内计时器，与时区无关）；
  所有能量、点数、∫ρ、跨度数值（与时钟无关）；护栏结论（归档复现差 0.0000）。
- 绝对时刻只能给区间：两次运行（B1 三小体系、B2 三个苯-X）都完成于
  2026-10-09T08:29Z 之前；精确到分钟的真实起点不可从产物反推，故不编。

## 处置

1. 文件名与内文不改——改了就等于编辑已登记的原始 stdout（本仓规矩：归档不编辑），
   而且 MANIFEST 已经登记了这两个名字对应的哈希。
2. 本说明即更正件，随目录一起入库；引用这两个产物时以本文件的日期为准。
3. 脚本已改为：`run_utc` 优先取外部传入的 `RUN_TS`（由宿主时钟在启动时算好），
   同时把 WSL 自己的 `date` 也打出来——**两个钟并排显示，偏差当场可见**，
   而不是等到取名时才发现。
4. 后续所有走 WSL 的运行按同一办法启动：`TS` 由 Git Bash 侧算出再传进去。

## 复查用

```bash
# 宿主与 WSL 两钟对照（任一方向偏 >60 s 就先修钟再跑）
echo "host: $(date -u +%FT%TZ)"; wsl -e bash -lc 'echo "wsl : $(date -u +%FT%TZ)"'
```

## 追加（同日）：共享的 `_rc` 被下一次运行覆盖，改为"每次运行一个退出码文件"

发现方式：收工闸门报 `common_grid/_rc` 与已登记哈希不符。查内容：它写着 `rc=143`
——那是后来我在本机起的苯二聚体(A)、被我用 kill 终止时留下的 SIGTERM 码，
它覆盖掉的是 B1/B2 两次运行的 `rc=0`。**一个共享标记文件被多次运行覆盖，
本身就是"记录会说谎"的另一种形态**，与三处时钟问题同源。

处置：

1. 删除共享的 `_rc`。
2. 改为每次运行一个：`<产物名>.out.rc`。本轮补出两个，内容都是 `rc=0`——
   依据是（i）删除前已登记的 `_rc` 哈希对应内容 `rc=0`（两次运行相继通过），
   （ii）两个 .out 的末行都是脚本里**只有成功路径才会打印**的那句
   "全部体系护栏通过……"。没有任何一处是靠回忆或推测填的。
3. 被 kill 的那次本机运行没有产物（.out 只有表头，已删），因此不设 rc 文件留档；
   它的存在只记在这里，供审计对账。
